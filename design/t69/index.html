Cases this request does not decide

Each case becomes a special case in code if nobody decides it. My suggestion is after the dash.

  1. A borderline request. "Show me how dark mode would look." Is a mock-up a build? — Treat anything that changes a file or starts an agent run as a build; the helper may only describe.
  2. A lead loses the role between the request and the confirm. — The bot checks the role again at the press; the press fails with a note.
  3. Two leads start the same feature within minutes. — The second confirm card says "Jon asked for a similar session at 14:05" and asks again.
  4. Too many sessions on the Mac. How many chief sessions may run at once? — Decided by Erick (D5): 2 at most. Suggestion: a third start waits in a queue that the bot shows.
  5. Direct messages to the bot. — The bot answers no direct messages and says to use #ask-sage, so every answer stays visible.
  6. An edited or deleted mention after the reply. — The bot does not change its answer; a deleted request cancels an open confirm.
  7. Secrets in an answer. The helper reads the logbook and the repository. — It never reads .env files, the bridge config or the gate file; answers go through the same allow-list cleaner as reasons.
  8. A private repository. Can an apprentice without GitHub access read code through the bot? — Yes for the shared project only, because the owner shares it on purpose (D2).
  9. A long answer over Discord's 2,000 characters. — The bot cuts it and attaches the full text as a .md file.
  10. An owner who is also a lead asks for a session start in Discord. — No approval card for the owner's own request in variant A.

Options I rejected, and why

Slash commands only, no mentionsExact and private, but a free question ("why do we vote in threads?") has no fixed command, and private answers teach nobody else. D13 keeps both forms.
The live chief answers every questionIt stops the chief's work for each question, and Discord text reaches the session that writes code.
A private reply to every refusal of a mentionDiscord cannot reply in private to a plain message. Only a button press or a slash command gets an ephemeral reply. A direct message hides the rule from the team.
A "New session" form for apprenticesThe owner said apprentices do not ask for builds. An "Ask a lead" button keeps the idea without the right (moment 5).
A link to a newly published page for each artifact requestEach publish needs the owner's yes, so the reply waits for hours. Images already in the project answer at once (moment 3).
